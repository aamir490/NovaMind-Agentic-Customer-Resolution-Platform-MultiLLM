# Local development

Phase 17 adds an optional [local container workflow](phase-17-containers.md) alongside the commands below. Container configuration, 14 focused tests, Compose validation, and an offline frontend build are verified; actual image builds/runtime remain unverified while the Docker engine is unavailable. Authentication still defaults to an empty registry; no anonymous business access or frontend login is added.

The current backend includes the Phase 1 domain and Phase 2 business operations; the frontend adds a Phase 3 read-only case-review screen. See [the domain walkthrough](phase-1-domain.md) and [UI walkthrough/test commands](phase-3-case-review.md). Restarting or reloading the backend clears all customer, order, and case data; run one backend worker.

## Prerequisites

- Python 3.12 for the backend baseline.
- Node.js 24 with npm for the frontend baseline.
- Two terminals opened at this repository root.

No AWS account access, credentials, API key, or `.env` file is needed for Phase 0. The official [Vite guide](https://vite.dev/guide/) and [FastAPI first steps](https://fastapi.tiangolo.com/tutorial/first-steps/) provide framework background.

## Phase 0C verification boundary

Phase 0C uses the already installed environment. Do not run installation/setup commands, query package registries, or recreate environments during this phase. If dependencies are missing or broken, stop and report the issue. All verification requests must stay on local loopback. The reference links above are background reading, not verification steps.

The first-time setup commands below are retained for a future explicitly authorized setup; they are not instructions to install during Phase 0C. Python `requirements.txt` is an exact-version `pip freeze` snapshot without artifact hashes. The npm lock is generated by npm. Neither establishes production readiness.

## First-time setup reference — not part of Phase 0C

Backend, from the repository root:

```powershell
python -m venv backend/.venv
./backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
```

Frontend, from `frontend/`:

```powershell
npm ci
```

## Backend (PowerShell, terminal 1)

```powershell
./backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

Calling the virtual environment's Python directly avoids PowerShell activation-policy issues. On macOS/Linux, use `python3` to create the environment and `backend/.venv/bin/python` for the remaining commands.

## Frontend (terminal 2)

```powershell
cd frontend
npm run dev
```

Open `http://127.0.0.1:5173` and choose **Check local API**. You should see that the local API is responding. This proves the development page can reach FastAPI through the Vite proxy; it does not test any future AWS dependency.

If PowerShell blocks `npm.ps1`, use `npm.cmd` for the npm commands on Windows.

## Verify the scaffold

From a third PowerShell terminal at the repository root while both servers are running:

```powershell
./backend/.venv/Scripts/python.exe -m pip check
Invoke-RestMethod http://127.0.0.1:8000/api/health
Invoke-RestMethod http://127.0.0.1:5173/api/health
```

Both should return `status: ok` and `service: novamind-api`. FastAPI also provides interactive API documentation at `http://127.0.0.1:8000/docs`.

Build the frontend:

```powershell
cd frontend
npm run build
```

This writes ignored static assets to `frontend/dist/`. A successful build is not deployment verification. `npm run preview` can inspect those assets, but its server has no API proxy.

For a failure demonstration, stop the backend with Ctrl+C, then choose **Check local API** again. The page should report the unavailable API and allow another attempt. Restart the backend and retry to demonstrate recovery.

## Troubleshooting

- **Port already in use:** stop the conflicting local process or choose a coordinated port change. Vite uses strict ports so it will not silently select another address. If changing the backend port, also change the proxy target in `frontend/vite.config.js`.
- **Page works, API fails:** confirm FastAPI is running on port 8000 and test its URL directly. Use `npm run dev` for the connected demo.
- **Import errors:** use the repository root and the virtual environment Python shown above. During Phase 0C, stop and report missing/broken dependencies instead of installing or recreating the environment.
- **Unexpected versions:** inspect `python --version`, `node --version`, and `npm --version` before changing dependencies.

Stop each development server with Ctrl+C when finished.
